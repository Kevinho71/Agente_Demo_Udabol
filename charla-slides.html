Texto entra. Texto sale.

Un modelo de lenguaje es la IA que hay detrás de Gemini o ChatGPT. Recibe texto y devuelve texto. Nada más.

entra: ¿Cuál es la capital de Bolivia?

SucreeslacapitalconstitucionaldeBolivia.

Escribe pieza por pieza: en cada paso adivina cuál debería ser la siguiente.

El modelo no recuerda nada.

Cada llamada empieza de cero. Es como hablar con alguien que acaba de entrar a la sala: no sabe lo que se dijo antes.

La memoria es una ilusión útil. Recuerda porque tu código le entrega todo el montón de hojas de la conversación en cada llamada. Si no las pasas, no las recuerda.

Las instrucciones del modelo.

system prompt

Una hoja fija que va siempre primero. La escribes tú; el usuario nunca la ve.

Lo que recibe el modelo, en orden:

Instrucciones→Herramientas→Pregunta
Instruccionessystem prompt
  • Rol“Eres un asistente de catálogo.”
  • Idioma y tono“Responde en español.”
  • Uso de herramientas“Si necesitas datos, pide una herramienta.”
  • Límites“No inventes.”

Le entregas un menú de herramientas.

Como la carta de un restaurante: cada herramienta dice cómo se llama, para qué sirve y qué datos necesita.

Menú de herramientas
  • Consultar productosLee el catálogo. Necesita: orden y cantidad.
  • Crear productoAgrega uno nuevo. Necesita: nombre, precio y stock.
  • Las que tú definas…Cada una con su descripción.

El modelo no ve tu código ni tu API: solo lee este menú. Cada herramienta es un botón que tu código conecta con una función de tu API.

El modelo propone, tu código ejecuta.

La regla que sostiene todo lo demás.

Un agente es un bucle.

1Preguntar 2Revisar 3Ejecutar 4Devolver ↻ se repite ✓Fin

En cada vuelta el modelo recibe estas tres cosas. Pulsa → para recorrer el bucle.

1 · Preguntar. Tu código se las entrega juntas.

2 · Revisar. El modelo no ejecuta nada: escribe una nota, y tu código la revisa.

3 · Ejecutar. Tu código usa la herramienta de verdad y consulta tu API.

4 · Devolver. Los datos entran como hoja nueva y se vuelve a preguntar.

Fin. Cuando en vez de una nota hay texto, el bucle termina y se responde.

El viaje completo de una consulta.

Pulsa → para seguir una consulta de principio a fin.

1. El usuario escribe en el chat. La pregunta llega a tu código, no al modelo.

2. Tu código arma el paquete de hojas (instrucciones, menú y pregunta) y se lo envía al modelo.

3. El modelo no tiene los datos. Responde con una nota pidiendo una herramienta.

4. Tu código comprueba que esa herramienta esté en su lista y pide los datos a tu API.

5. Tu API devuelve los datos reales. El modelo todavía no los ha visto.

6. Tu código se los entrega como una hoja nueva: es la segunda vuelta del bucle.

7. Con los datos delante, el modelo redacta la respuesta en texto.

8. Tu código se la devuelve al usuario. El modelo nunca tocó tu base de datos.
